Day 1 · 10/12 周一

指标、流水线、分支预测

目标：Amdahl 正着算、反着算都能 1 分钟内算完；给一个分支 pattern，能手算 1-bit、2-bit 和历史预测器的稳态准确率。

1. 性能指标与评估

Day 1

性能怎么算

  • Latency（单个任务的时间）和 throughput（单位时间完成的任务数）是两回事，不一定成反比。
  • Speedup = Time_old / Time_new，大于 1 表示变快。
  • Iron Law：Time = IC × CPI × T_clk。IC 由 ISA 和编译器决定，CPI 由 ISA 和微架构决定，时钟由微架构和工艺决定。
  • CPI = Σ 比例ᵢ × CPIᵢ。

Amdahl 与 Lhadma

  • Speedup = 1 / ((1−F) + F/S)，F 是改进前那部分占的时间比例。
  • 上限 1/(1−F)。反解 S = F / (1/Speedup − (1−F))。
  • 多个改进作用在不重叠的部分：新时间 = 没改的部分 + Σ Fᵢ/Sᵢ。不能把各自的加速比相乘。
  • Lhadma：别为了加速罕见情况让常见情况变慢。

Benchmark 与平均

  • Benchmark 种类：真实应用 → 应用核心 kernel → 合成程序 → 峰值性能，越往后越不代表真实情况。
  • 对 speedup 求平均用几何平均：(Πsᵢ)^(1/n)。几何平均的比值 = 比值的几何平均，所以换参照机器结论不变。
  • 对执行时间可以用算术平均，但不能拿算术平均后的 speedup 去比较。

功耗与制造成本

  • 动态功耗 P = ½ · C · V² · f · α（α 是活动因子）。降电压最有效（平方关系），但电压低了频率也得降。
  • 总功耗 = 动态 + 静态（漏电）。电压降得太低时，为了保持速度要降阈值电压，漏电反而上升，所以电压有一个最优点。
  • 芯片面积越大，良率越低，每颗芯片成本增长比面积快（超线性）。工艺进步可以选“同面积更快”或“同性能更便宜”。
易错 F 是原来的时间比例。题目要是说“优化后有 x% 时间在某部分”，要先换算回原来的比例。 反解 S 时，如果算出负数或无穷大，说明目标超过了上限，题目问的就是“不可能”。

2. 流水线复习

Day 1

冒险

  • Structural：资源不够（例如只有一个存储器端口）。
  • Data：RAW 是真冒险；在简单的按序 5 级流水线里，WAR 和 WAW 不会出问题。解决方法：forwarding，不行就 stall（load-use 通常要 stall 1 拍）。
  • Control：分支。在第 k 级 resolve，预测错就要 flush 掉 k−1 条指令。
  • 依赖（dependence）是程序本身的性质；冒险（hazard）是依赖和流水线结构碰到一起时才出现。

CPI 与流水线深度

  • CPI = 1 + Σ(事件频率 × stall 周期)。
  • 分支部分：分支比例 × 错误率 × 惩罚。
  • 流水线越深 → 时钟越快，但惩罚越大，每级的 latch 开销占比也越高。比较两个设计用每条指令的时间 CPI / f。
  • 只看性能，最佳深度大约 30–40 级；把功耗也考虑进去，大约 10–15 级。
练习：M1–M4P1–P2

3. 分支预测

Day 1

要解决的问题：取指时只知道 PC，就要决定下一条从哪取。需要预测两件事：是不是分支、跳不跳（方向），以及跳到哪（目标地址）。

预测器怎么工作擅长 / 弱点
Not-taken永远预测不跳，什么也不存最便宜；对循环分支很差
BTB用 PC 低位索引，存目标地址和 tag解决“跳到哪”；只存跳转的分支就够了
1-bit (BHT)记住上一次的结果每次结果变化都错 1 次；循环分支每次退出错 2 次
2-bit counter0、1 预测 N，2、3 预测 T，结果是 T 就 +1，N 就 −1偶尔一次异常不会改变预测；但对 TNTN 这种交替 pattern 很差
History（n 位 + 2ⁿ 个 counter）用该分支最近 n 次的结果选一个 counter能学会周期性 pattern，周期越长通常需要越多历史位；n 越大越贵（counter 数是 2ⁿ），训练也越慢
PShare每个分支有私有历史，和 PC XOR 后去索引一张共享的 counter 表适合单个分支自己的规律（短循环、交替 pattern）
GShare一个全局历史寄存器 XOR PC适合分支之间相关的情况（if a… if b…）
Tournament两个预测器加一个 meta-predictor（也是 2BC）决定听谁的结合两者优点（例如 pshare + gshare）
Hierarchical便宜的预测器管大部分分支，难预测的才交给贵的预测器比 tournament 省存储空间
RAScall 时把返回地址 push 进栈，ret 时 pop专门预测函数返回；栈满时覆盖最老的

手算稳态准确率的步骤

  • 写出一个完整周期的 pattern。
  • 从初值开始模拟，直到某个周期开头的 counter 状态和上一个周期开头一样，这时进入稳态。
  • 数稳态里一个周期错几次，准确率 = 对的次数 / 周期长度。
  • 历史预测器要为每个历史值单独记一个 counter，各自更新。
  • 求最少历史位数：列出所有长度为 n 的滑动窗口（首尾要接起来），每个窗口后面跟的结果都唯一时，n 位就够了。

Predication

  • If-conversion：两条路径都执行，最后用条件 move（MOVZ/MOVN）选出正确结果。
  • Full predication：每条指令带一个 predicate 寄存器，predicate 为假的指令变成 NOP（例如 Itanium）。
  • 划算的条件：多执行的指令数 < 错误率 × 惩罚，也就是分支难预测、两条路径都很短的时候。
  • 循环分支、容易预测的分支不值得做 predication。
易错 2-bit counter 的初值和阈值要看题目（通常初值 0 = strong not-taken）。T、N 段都很短时，2-bit 可能比 1-bit 还差。 历史位要包括周期边界，例如 …N N | T T… 这个窗口也要算进去。
练习：B1–B3

Day 2 · 10/13 周二

ILP、Tomasulo、ROB

目标：给一段代码，能数出 RAW、WAR、WAW 并算 ILP；一张 6–7 条指令的 ROB 时序表能在 15 分钟内填完且没有错。这是分值最大的一块，今天要多花时间。

4. ILP 与寄存器重命名

Day 2

三种依赖

  • RAW（true dependence）：后面的指令读前面写的寄存器。只能等，重命名去不掉。
  • WAR（anti）：后面的指令写前面读的寄存器。
  • WAW（output）：两条指令写同一个寄存器。
  • WAR、WAW 是“名字依赖”（false dependence），重命名后消失。
  • 数 RAW 时要找最近一次写这个寄存器的指令，不是第一次写的那条。

重命名（RAT）

  • RAT：每个架构寄存器对应一项，指向当前最新的那个物理位置（物理寄存器 / RS 标签 / ROB 条目）。
  • 读源寄存器：查 RAT 得到最新名字。写目的寄存器：分配一个新名字，并更新 RAT。
  • 重命名后只剩 RAW 依赖，乱序执行才有空间可以利用。

ILP 怎么算

  • 假设理想处理器：重命名完美、资源无限、一个周期就能取完所有指令、分支预测完美。
  • 每条指令的完成周期 = 它所有 RAW 来源中最晚的完成周期 + 自身延迟（题目通常设为 1）。
  • ILP = 指令数 / 最后完成的周期。

ILP 和 IPC 的区别

  • ILP 是程序本身的性质，前提是理想处理器。
  • IPC 是在真实处理器上跑出来的，受发射宽度、执行单元数量、窗口大小限制。IPC ≤ min(ILP, 发射宽度)，大致如此。
  • 有限宽度的题：每个周期最多选 w 条，依赖关系照样要满足。
练习：I1

5. Tomasulo（指令调度）

Day 2

结构

  • Instruction Queue → Issue（按序）：要有空的 RS；查 RAT，把源操作数的值或标签写进 RS；把目的寄存器在 RAT 里改成这个 RS 的标签。
  • Dispatch：操作数都齐了就送去执行单元。同时有多条就绪时，一般选最老的。
  • Write result / Broadcast：结果和标签放上 CDB；等这个标签的 RS 抓取值；寄存器文件和 RAT 里如果还指向这个标签，就更新。

局限

  • 结果直接写进寄存器文件，没有精确异常，分支预测错了也很难恢复。这就是为什么要有 ROB。
  • 原版 Tomasulo 里 load/store 按序执行。
  • 同一周期能不能 issue 和 dispatch、广播和 dispatch 是否可以同周期，这些细节以题干为准。

6. ROB（重排序缓冲）

Day 2

为什么需要 ROB

  • 乱序执行，按序 commit。commit 之前的结果都只是“临时”的。
  • 异常：等出错的指令到达 ROB 头部时再处理，它前面的都已经 commit，后面的全部丢掉，得到精确异常。
  • 分支预测错误：分支在 commit（或 resolve）时，把它后面的 ROB 条目全部清掉。

ROB 版本的流程

  • Issue：要有空 RS 和空 ROB 条目；RAT 指向 ROB 条目（不再是 RS）。
  • Dispatch / Exe：和 Tomasulo 一样。RS 在开始执行时就可以释放（因为标签现在是 ROB#）。
  • Broadcast：结果写进 ROB 条目，并发给等待的 RS。
  • Commit：ROB 头部的指令已完成时，把值写进 ARF；如果 RAT 里这个寄存器还指向这条 ROB 条目，就把 RAT 改回指向 ARF。然后释放这个 ROB 条目。

时序表做题清单（照这个顺序做）

1. Issue  ：按序；需要 空RS && 空ROB
            RS 在 "Exe 开始那拍" 释放，同拍即可被占用
            ROB 在 "commit 那拍" 释放，下一拍才可用
2. Exe    ：≥ Issue+1；≥ 每个源的 BCast+1
            非流水单元：上一条 Exe+lat 之前不能开始
            流水单元：每拍只能开始 1 条，老的优先
3. BCast  ：≥ Exe+lat；每拍只能广播 1 个，老的优先
4. Commit ：≥ BCast+1；≥ 上一条 Commit+1（按序，每拍 1 条）
5. 回头检查：每算出一个 Exe/Commit，看有没有让后面
            卡住的 Issue 可以提前
易错 只看 RS 不看 ROB：ROB 小的时候，issue 常被 ROB 卡住，要等最老的那条 commit 之后的下一拍。 广播冲突把指令往后推之后，依赖它的指令 Exe 也要跟着往后推。 WAR 的源（读的是旧值）不用等后面写它的那条指令。 在某条指令广播的同一拍 issue 的指令能不能拿到值，以题干为准（sample 的规则是能拿到）。
练习：R1、R2，然后闭卷做一遍 Sample Test Q4

7. 访存顺序（LSQ）

Day 3

规则

  • Store 要等到 commit 才写 cache，否则预测错或异常时没法撤销。
  • LSQ 按程序顺序存放 load 和 store，记录地址、值和是否完成。
  • Load 执行时往更老的方向查：找地址相同且最近的那条 store，用它的值（store-to-load forwarding）；没找到才去读 cache。
  • 寄存器重命名只管寄存器，经过内存的 RAW 要靠 LSQ 发现。

老的 store 地址还不知道时

  • 保守：等所有更老的 store 地址都算出来再执行 load，安全但慢。
  • 激进：先执行 load（读 cache）。等 store 算出地址后，检查后面已经执行的 load，地址相同就把那个 load 和之后的指令全部重做。
  • 大多数 load 和前面的 store 地址都不同，所以激进做法通常更快。
  • 同一地址上的 store 之间、load 之后的 store 也要保证顺序（WAR/WAW 经过内存）。按序 commit 已经保证了这一点。
练习：L1

8. 编译器提高 ILP

Day 3

四种手段

  • Tree height reduction：((a+b)+c)+d → (a+b)+(c+d)，依赖链从 3 变 2。要求运算满足结合律（浮点数严格来说不满足）。
  • Instruction scheduling：把不相关的指令挪进 stall 的位置，改指令时要注意偏移量和寄存器。
  • Loop unrolling：把 k 次迭代合成一次，循环开销（ADDI、BNE）从每次迭代 1 份变成每 k 次迭代 1 份，而且有更多独立指令可以调度。
  • Function inlining：去掉 call/ret 开销，扩大调度范围；代价是代码变大。

展开的计算

  • 指令数：(N/k) × (k × 循环体 + 开销)。
  • 周期数：画调度表，每条指令放在“所有来源 + 延迟”之后最早的空位。
  • 展开时要用不同的寄存器（相当于编译器自己做重命名），load/store 的偏移量要按迭代次数调整。
  • 缺点：代码变大，可能导致 I-cache miss；需要更多寄存器；N 不是 k 的倍数时还要额外处理剩下的迭代。
练习：V1

9. VLIW

Day 3
超标量乱序VLIW
谁找并行硬件（RAT、RS、ROB）编译器，把独立操作打包进一条长指令
硬件复杂度、功耗高低，不做依赖检查
代码大小正常填不满的槽要放 NOP，代码膨胀
延迟不确定时（cache miss）能动态适应编译器预知不了，只能整体 stall
兼容性同一个 ISA 可以换不同宽度的实现宽度和延迟写死在指令里，换一代硬件可能要重新编译

VLIW 常配的技术

  • 全部指令带 predicate（把分支变成 if-conversion），循环展开，software pipelining，trace scheduling。
  • EPIC/Itanium 的折中做法：用一个位标明“这组指令可以并行”，而不是固定宽度。
  • 适合规整的循环（DSP、多媒体），不适合分支多、cache miss 多的通用代码。

Cache、虚拟内存、高级 Cache

目标：地址位数划分、AMAT、LRU 模拟、页表大小、VIPT 容量上限都能直接算；能把每个高级 cache 技术归到“降 hit time / 降 miss rate / 降 miss penalty”中的一类。

10. Cache 复习

Day 4

基本计算

  • 局部性：时间局部性（刚访问过的还会访问）、空间局部性（相邻的也会访问）。
  • AMAT = HT + MR × MP。
  • offset = log₂(块大小)；#sets = 容量 / (块大小 × 路数)；index = log₂(#sets)；tag = 地址位数 − index − offset。
  • 直接映射 = 1 路；全相联 = 1 个 set，没有 index 位。
  • 每个块的元数据：valid 位、tag，write-back 还要 dirty 位，LRU 还要计数器。

替换与写策略

  • 替换策略：Random、FIFO、LRU、NMRU（不替换最近用过的那块）、PLRU。
  • LRU 计数器实现：N 路，每块 log₂N 位。访问某块时，它的计数器设为 N−1，原来比它大的计数器各减 1；替换时选计数器为 0 的块。
  • Write-through：每次写都写到下一级，一般配 write buffer。Write-back：只在替换脏块时才写回。
  • Write-allocate：写 miss 时把块调进来（通常和 write-back 搭配）。No-write-allocate 通常和 write-through 搭配。

11. 虚拟内存

Day 4

地址翻译

  • VA = VPN | page offset；PA = PFN | page offset（offset 不变）。offset 位 = log₂(页大小)。
  • 单级页表大小：2^(VA位 − offset位) × PTE大小。例如 32 位 VA、4 KB 页、4 B PTE，就是 4 MB，每个进程一份。
  • 多级页表：VPN 拆成几段，只给实际用到的部分分配下一级表。32 位按 10/10/12 拆时，每张表都是 1024 × 4 B = 4 KB。
  • PTE 内容：PFN、valid（无效就触发 page fault，由 OS 从磁盘调入）、dirty、权限位。

TLB

  • TLB 是 PTE 的 cache：小（几十到几百项）、相联度高，命中时 1 拍就能完成翻译。
  • TLB miss：去查页表（page walk），由硬件或 OS 软件处理。
  • TLB reach = 项数 × 页大小。工作集超过 reach 时，TLB miss 会急剧增加；大页能提高 reach。
  • 多级 TLB 和多级 cache 的道理一样。

12. 高级 Cache 技术

Day 4
目标技术要点
降 hit time小而简单的 L1容量小、路数少，hit 更快
VIPT用虚拟地址的 index 访问 cache，同时查 TLB，用物理 tag 比较。无 aliasing 的条件：容量 ≤ 路数 × 页大小
Way prediction先只查预测的那一路，猜错了再查其他路。HT = p×快 + (1−p)×慢
NMRU / PLRU近似 LRU，更新更便宜
降 miss rate更大的块compulsory miss 减少；但块数变少，conflict miss 可能增加，miss penalty 也变大
更大容量 / 更高相联度分别减少 capacity miss 和 conflict miss，代价是 hit time 变长
Prefetching软件 prefetch 指令；硬件 stream buffer、stride、correlating prefetcher。太早会被替换掉，太晚来不及，没用的预取还会污染 cache
Loop interchange交换循环嵌套顺序，让内层循环按内存顺序访问（C 语言数组是行优先）
Blocking (tiling)把大矩阵拆成能放进 cache 的小块分别处理
降 miss penalty非阻塞 cachehit-under-miss、miss-under-miss（memory-level parallelism），用 MSHR 记录还没完成的 miss，同一个块的多次 miss 合并到一个 MSHR
多级 cacheAMAT = HT₁ + MR₁(HT₂ + MR₂·MP₂)，MR₂ 用 local miss rate
Write buffer写回的脏块先放进 buffer，读 miss 可以先处理

3C 分类

  • Compulsory：第一次访问这个块，无限大的 cache 也会 miss。
  • Capacity：同样大小的全相联 cache 也会 miss（容量不够）。
  • Conflict：全相联不会 miss，但组相联或直接映射会 miss（同一个 set 里互相挤掉）。
  • 分类方法：对同一条访问序列，分别用“无限大”“同样大小的全相联 LRU”“实际 cache”模拟，逐级比较。

多级 cache 的概念

  • Local miss rate = 本级 miss / 本级访问；global = 本级 miss / CPU 总访问。global₂ = MR₁ × local₂。
  • L2 的 local miss rate 往往看起来很高（容易命中的访问都被 L1 挡掉了），这不代表 L2 不好。
  • Inclusion：L1 的内容都在 L2 里。不会自动成立，L2 替换一个块时必须把 L1 里对应的块也 invalidate。另一种做法是 exclusive（不重复存放）。
易错 VIPT 的条件是 每一路 的大小（容量 / 路数）≤ 页大小，不是总容量 ≤ 页大小。 两级 AMAT 里，括号内乘的是 L2 的 local miss rate；题目给的是 global 的话，要先除以 MR₁。 LRU 模拟题要同时追踪“谁在 cache 里”和“使用的先后顺序”，命中也会改变顺序。
