性能指标与 Amdahl 定律

Week 1 · 对应 sample Q2

要点

  • Amdahl：Speedup = 1 / ((1−F) + F/S)，F 是原来执行时间中被加速部分的比例。
  • 上限：S→∞ 时 Speedup_max = 1/(1−F)。sample 里 2% 不能优化，上限就是 1/0.02 = 50。
  • 反解 S：S = F / (1/Speedup − (1−F))。
  • Iron Law：CPU time = IC × CPI × T_clk = IC × CPI / f。
  • 指令混合：CPI = Σ (比例ᵢ × CPIᵢ)。
  • 多个 benchmark 的平均 speedup 用几何平均（换参照机器结论不变）。不要直接对 speedup 做算术平均。
  • Lhadma 定律（Amdahl 的反面）：别为了加速罕见情况而让常见情况变慢。

分支预测与 Predication

Week 2 · 对应 sample Q3

要点

  • 1-bit counter：预测上一次的结果。在一个周期性 pattern 里，每次结果改变（T→N 或 N→T）都错一次，所以每个周期错 2 次。
  • 2-bit counter（0、1 预测 N；2、3 预测 T，初值 0）：要连续错两次才改变预测。T/N 段很短时可能比 1-bit 还差（sample 里就是 42.86% < 71.43%）。
  • History predictor（n 位历史 + 2ⁿ 个 counter）：用最近 n 次结果作为索引选 counter。
  • 求最少历史位数：在一个周期里写出所有长度为 n 的窗口，看每个窗口后面跟的结果是否唯一。都唯一时，n 就够了。
  • 做稳态题的方法：先模拟两三个周期，直到状态开始重复，再数一个周期里错几次。第三秒的准确率就是稳态准确率。
  • BTB 预测目标地址，BHT/PHT 预测方向，RAS 预测函数返回地址。Tournament 预测器用一个 meta-predictor 在两个预测器间选择。
  • Predication / if-conversion：两条路径都执行，用 predicate 或 MOVZ/MOVN 丢掉不需要的结果。不会再预测错，但要多执行指令。分支难预测、两条路径都短时最划算。

ILP、依赖与重命名

Week 3

要点

  • RAW（真依赖）：后面的指令读前面写的值。重命名去不掉。
  • WAR（反依赖）、WAW（输出依赖）是名字依赖，用寄存器重命名（RAT）就能去掉。
  • 理想处理器的 ILP：资源无限、重命名完美、每条 1 周期，只受 RAW 限制。ILP = 指令数 / 周期数。
  • 做法：每条指令的周期 = 它所有 RAW 来源中最晚完成周期 + 1。没有依赖的放在第 1 周期。
  • Tomasulo：Issue（按序，需要空 RS） → Dispatch（操作数齐了才执行） → Write result（CDB 广播）。RAT 指向“将产生这个值的 RS/ROB 条目”。

ROB 时序表

Week 4 · 对应 sample Q4（分值最大）

规则（和 sample 一样，要背熟）

  • Issue：按程序顺序，每周期 1 条；需要同时有空 RS 和空 ROB 条目。
  • RS 释放：指令开始执行的那个周期释放，同一周期就能 issue 新指令进来。
  • ROB 释放：在 commit 的那个周期释放，下一个周期才能被新指令使用。
  • Exe：最早在 issue 的下一周期；操作数在周期 X 广播，最早 X+1 开始执行。在广播的同一周期 issue 的指令也能拿到值（sample 里 I6 就是这样）。
  • BCast：最早 = Exe + latency。每周期只能广播 1 个，冲突时老指令优先，新的往后排。
  • 非流水单元：Exe 到 Exe+lat−1 一直被占用，下一条最早 Exe+lat。流水单元：每周期能开始 1 条，冲突时老指令优先。
  • Commit：按序，每周期 1 条，最早在 BCast 的下一周期。
做题顺序：先把每条的 Issue 填出来（检查 RS 和 ROB 够不够），再按依赖填 Exe，接着处理执行单元冲突，然后处理广播冲突，最后按顺序填 Commit。每填一格，都回头看一下有没有因此空出 RS 或 ROB 条目。

访存顺序（LSQ）

Week 5

要点

  • Store 在 commit 时才写进 cache/内存（不然没法撤销）。
  • LSQ 按程序顺序保存 load 和 store。load 执行时往前（更老的方向）找地址相同的最近一条 store，找到就 store-to-load forwarding，找不到才去读 cache。
  • 如果更老的 store 地址还没算出来，load 可以等（保守），也可以先执行（激进）。激进做法下，store 地址算出来后要检查后面已经执行的 load，地址相同就重新执行该 load 及其之后的指令。
  • RAW 依赖可能通过内存发生，寄存器重命名看不到这种依赖，要靠 LSQ。

编译器 ILP 与 VLIW

Week 6

要点

  • Tree height reduction：把 ((a+b)+c)+d 改成 (a+b)+(c+d)，依赖链变短（要求运算满足结合律）。
  • Instruction scheduling：把不相关的指令挪进 stall 的空位。
  • Loop unrolling：减少循环开销指令（ADDI、BNE），还给调度更多可以填空位的指令。代价是代码变大、用更多寄存器。
  • 展开后指令数：(迭代数 / k) × (k × 循环体 + 开销)。
  • VLIW：编译器把独立指令打包成一个长指令字，硬件不检查依赖。优点是硬件简单、省电；缺点是填不满时要塞 NOP，代码膨胀，编译器无法预知 cache miss 这类延迟，换一代硬件可能要重新编译。

Cache 复习与虚拟内存

Week 7

要点

  • AMAT = hit time + miss rate × miss penalty；两级 cache：AMAT = HT₁ + MR₁ × (HT₂ + MR₂_local × penalty_mem)。
  • 地址划分：offset = log₂(block)，#sets = size/(block × ways)，index = log₂(#sets)，tag = addr位数 − index − offset。
  • LRU：每次访问把该块移到“最近使用”一端，替换时踢掉最久没用的。N 路 LRU 每块需要 log₂N 位计数器。
  • Write-back 需要 dirty 位；write-through 一般配 write buffer。Write-allocate：写 miss 时把块调进 cache。
  • 页表大小 = 2^(VA位数 − page offset 位数) × PTE大小。多级页表只给用到的部分分配空间。
  • TLB reach = TLB条目数 × 页大小。

高级 Cache

Week 8

要点

  • 降 hit time：VIPT（TLB 和 cache 并行查）、way prediction（先猜一路，猜错再查其他路）、小而简单的 L1、replacement 用 NMRU/PLRU 代替真 LRU。
  • 降 miss rate：3C = Compulsory（第一次访问）、Capacity（无限大全相联也会 miss 的那部分之外，由容量不够引起）、Conflict（全相联不会 miss，组相联会）。更大的块减少 compulsory miss，但可能增加 conflict 和 miss penalty。Prefetch、loop interchange、blocking。
  • 降 miss penalty：非阻塞 cache（hit-under-miss、miss-under-miss，靠 MSHR 记录未完成的 miss）、多级 cache。
  • Local miss rate = 本级 miss 数 / 本级访问数；global = 本级 miss 数 / CPU 总访问数。
  • Inclusion：L1 的内容一定在 L2 里，需要特别维护（L2 替换时要 invalidate L1 里对应的块），不会自动成立。
