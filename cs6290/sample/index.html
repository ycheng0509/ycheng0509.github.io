Question 2 · 8 ptsAmdahl

We are (manually) optimizing a program that spends 2 % (percent) of its execution time on disk accesses. We are optimizing the processor, so we cannot apply any optimizations to disk accesses.

Complete the following statements (your answers should be numbers):

To get a speedup of 25 on the entire program we need our optimizations to produce a speedup of at least on the source code we do have.
No matter how good our optimizations are, the overall speedup we can achieve can never exceed .
解析

25 = 1/(0.02 + 0.98/S) → 0.02 + 0.98/S = 0.04 → 0.98/S = 0.02 → S = 49。

上限：S→∞ 时 1/0.02 = 50。

Question 3 · 15 pts分支预测

A processor is executing a long-running program, in which the most frequently executed branch instruction is encountered 7 million times per second. This branch has the following sequence of outcomes (where N stands for not-taken and T stands for taken):

N, N, N, N, T, T, T, N, N, N, N, T, T, T, N, N, N, N, T, T, T, etc.

In other words, this branch has a repeating pattern where it is not taken four times then taken three times.

For the first seven occurrences of this branch instruction, the following table shows the counter values for the one-bit counter predictor, along with its predictions, and the actual branch outcomes. Note that the counter starts out with an initial value of 0. Fill out the missing entries in the table:

Occurrence #Counter ValuePredicted OutcomeActual Outcome
1st0NN
2ndN
3rdN
4thN
5thT
6thT
7thT

Now suppose that we are measuring the accuracy of this branch during the third second of execution, i.e. after the predictor has already been trained by the first 14 million occurrences of this branch. To simplify things, you should assume that the predictor entries that are used for predicting this branch are only used for this branch, i.e. no other branches are interfering with the prediction, and that the initial values of all bits in the predictor were zeroes - but note that these values have been updated during the first two seconds of execution.

Based on this, complete the following statements (your answers should be numbers):

If we use a 1-bit counter predictor we get a third-second accuracy of percent.
If we use a 2-bit counter we get a third-second accuracy of percent.
If we use a global history predictor with one-bit history and 1-bit counters, we get a third-second accuracy of percent.
The cheapest global-history predictor (with 1-bit counters) that achieves perfect third-second accuracy has (how many?) bits of history.
解析

表格：1-bit counter 就是记住上一次的结果。前 4 次都是 N，counter 一直是 0；第 5 次是 T，所以第 6 次开始 counter = 1，预测 T。

1-bit 准确率：一个周期（7 次）里结果变化 2 次（N→T、T→N），各错 1 次 → 5/7 = 71.43%。

2-bit：稳态下每个周期开始时 counter = 3（刚经历了 3 个 T）。

actual : N  N  N  N  T  T  T
counter: 3  2  1  0  0  1  2   → 周期结束变回 3
pred   : T  T  N  N  N  N  T
correct: ✗  ✗  ✓  ✓  ✗  ✗  ✓   → 3/7 = 42.86%

1 位历史 + 1-bit counter：两个 counter，按上一次结果选，每个 counter 预测“上次遇到同样历史时的结果”。

上次=N 的情况：第 2,3,4,5 次（结果 N,N,N,T）
  ctrN 预测: T(上周期第5次留下) N  N  N   → 对 2 次
上次=T 的情况：第 6,7 次和下周期第 1 次（结果 T,T,N）
  ctrT 预测: N(上周期第1次留下) T  T      → 对 1 次
共 3/7 = 42.86%

最少历史位：3 位时 NNN 后面有时是 N（第 1–3 次之后）、有时是 T（第 2–4 次之后），冲突。4 位窗口：NNNN→T，NNNT→T，NNTT→T，NTTT→N，TTTN→N，TTNN→N，TNNN→N，全部唯一 → 4。

Question 4 · 25 ptsROB

A one-issue processor uses out-of order execution with a Reorder Buffer (ROB). The processor has four unified reservation stations (RS0 through RS3) and eight ROB entries (ROB0 through ROB7). There are two execution units. One unit can only do MUL instructions, has a 6-cycle latency, and is NOT pipelined. The other unit can do all other (non-MUL) instructions, has a 2-cycle latency, and IS pipelined. The result can be broadcast in the cycle after the execution is complete. Only one result can be broadcast in each cycle. A reservation station that has been used by an instruction is freed when the instruction is selected for execution, and another instruction can be issued into that RS during the first execution cycle of the original instruction. A ROB entry can be reused in the cycle after the one in which it was freed (you should know when that is). An instruction that is waiting for a result to be produced can begin execution in the cycle after the one in which its last missing operand is broadcast. All conflicts for resources are resolved in favor of the older instruction, i.e. the instruction that comes earlier in the program.

Assume that reservation stations and the ROB are all empty at the beginning of the starting cycle (Cycle 1), and that the processor has already fetched and decoded the following instructions, so they are all waiting to be issued at the beginning of the starting cycle (Cycle 1). We have filled out the first row of the execution timing table below. You need to fill the rest of it.

InstructionIssueExeBCastCommit
I1MUL R2, R1, R01289
I2MUL R2, R2, R2
I3ADD R3, R0, R4
I4ADD R4, R3, R2
I5ADD R1, R1, R1
I6ADD R3, R3, R3
解析

I2：Issue 2。要等 I1 的 R2（第 8 周期广播）→ Exe 9；MUL 单元第 2–7 周期被 I1 占用，第 8 周期起空闲，不冲突。9 + 6 → BCast 15，Commit 16。

I3：Issue 3，没有依赖 → Exe 4，BCast 6。Commit 要排在 I2 后面 → 17。

I4：Issue 4。R3 来自 I3（6），R2 来自 I2（15），最晚的是 15 → Exe 16，BCast 18，Commit 19。

I5：第 5 周期 RS 里只有 I2、I4（I1、I3 开始执行时已释放），ROB 8 项也够 → Issue 5。Exe 6，第 7 周期算完，最早第 8 周期广播，但第 8 周期给了更老的 I1 → BCast 9。Commit 20。

I6：Issue 6。R3 来自 I3，I3 在第 6 周期广播，同一周期 issue 的 I6 也能拿到值 → Exe 7，最早第 9 周期广播，但第 9 周期给了更老的 I5 → BCast 10。Commit 21。

这题里 RS 和 ROB 都没有卡住 issue，考点是广播冲突（I5、I6 各被推后一拍）和按序 commit（I3 早就做完了，也要等到 17）。题目页的 R1、R2 加上了 RS 满、ROB 满的情况。
